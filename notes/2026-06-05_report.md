## Route Model And Filtering

The route workflow was clarified as:

```text
enumerate all candidate routes
classify each route by branch deletion status
split/filter routes after enumeration
group routes by truncal tree when needed for H/T/B scoring
```

Current route categories:

```text
pure_gain
    Neither branch has deletion.

both_branch_deletion
    Both post-truncal branches contain at least one deleted truncal copy.
    This matches old SPUR's complex route definition.

one_branch_deletion
    Exactly one post-truncal branch contains deletion.
    These are included in SPUR mixed-gain-loss routes but excluded by old SPUR.
```

The new route-filtering layer lives in:

```text
src/spur/route_filter.py
```

It provides:

```text

split_routes
group_by_truncal
collect_h_by_truncal
RouteGroup.h_tensor
```

## Notation Correction

The large real-data TSV uses `x:y` as:

```text
total copy number : minor copy number
```

Therefore:

```text
3:1 -> total=3, minor=1 -> internal major=2, minor=1
2:1 -> total=2, minor=1 -> internal major=1, minor=1
4:2 -> total=4, minor=2 -> internal major=2, minor=2
```

The real-data parsers now use the `between_sample_cn` column from:

```text
/home/yunong-xia/Downloads/May_27_real_data_indices.tsv
```

and convert `total:minor` labels into internal allele-specific tuples only at
enumeration time.

This boundary is represented by:

```text
CopyNumberState
CopyNumberPair
```

in:

```text
src/spur/notation.py
```

## Truncal Filter Rule

For real-data CN pairs, the truncal cap is:

```text
max_truncal_cn = min(max(sample total CN) + 2, 6)
```

The post-truncal event cap is:

```text
max_branch_events = 5
```

This reproduces the old SPUR example for `3:1 vs 2:1`:

```text
max_truncal_cn = min(3 + 2, 6) = 5
pure_gain routes = 1
old SPUR complex routes = 198
old-style total = 199
```

which matches the old output line:

```text
out of 199
```
