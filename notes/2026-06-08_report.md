# June 8 Report

## Scope

Work focused on cleaning the public CN API, aligning route/scoring objects with
the current implementation, validating the score path, and adding a CLI
integration test for reads input and TSV output.

## CN API Convention

The public CN convention is now:

```text
total:minor
```

Function inputs and parsed CN tuples use:

```text
(total_cn, minor_cn)
```

Major copy number remains available only as a derived property inside route
objects and allele-tree math:

```text
major_cn = total_cn - minor_cn
```

Updated API behavior:

```python
parse_between_sample_cn("4:2_3:1") == ((4, 2), (3, 1))
```

Enumeration now accepts total/minor tuples:

```python
RouteEnumerator().enumerate((4, 2), (3, 1), ...)
TruncalEnumerator().enumerate_for_state(total_cn=3, minor_cn=1)
BranchEnumerator().enumerate(..., target_total_cn=3, target_minor_cn=1, ...)
```

Old-SPUR comparison code converts to allele-specific `(major_cn, minor_cn)`
only at the old-SPUR boundary.

## Route Objects

The route object layer is now centered in:

```text
src/spur_codex/route.py
```

`Branch` now exposes a canonical key:

```python
Branch.canonical_key
```

The key is a compact copy-fate string such as:

```text
1,0,2
```

This is used for route score tables together with:

```text
Route.truncal_key
Branch.canonical_key for branch1
Branch.canonical_key for branch2
```

## Route Score Results

`RouteScoreResult` now lives in:

```text
src/spur_codex/features.py
```

It wraps:

```text
routes: tuple[Route, ...]
scores: np.ndarray
```

Convenience methods:

```python
score_results.score_features()
score_results.route_score_table(seed)
```

`score_features()` produces a single-row feature dictionary with pure-gain and
mixed-gain-loss summary scores.

`route_score_table(seed)` produces a route-level table dictionary:

```text
truncal
branch1
branch2
score_seed_{seed}
```

This supports combining multiple seed-specific route-score tables by merging or
concatenating score columns after route alignment.

## Scoring Path

The current scorer API is:

```python
Scorer().score(
    alt1=alt1,
    dep1=dep1,
    alt2=alt2,
    dep2=dep2,
    routes=routes,
    sample1_pu=...,
    sample2_pu=...,
    sample1_prevalence=...,
    sample2_prevalence=...,
    burn_in=...,
    skips=...,
    n_samples=...,
    rng=rng,
)
```

The score calculation was validated on a small example. The manual rebuild used
the same lower-level steps as the scorer:

```text
sample joint VAFs
build B with binom_pmf_tensor
group routes by truncal tree
sample T per truncal group
build group H
call score_thb_shared_t_shared_b(T, H, B)
```

Manual scores matched `Scorer.score(...)` exactly for the tested example:

```text
scorer [-7.566294037012424, -6.814217054740981]
manual [-7.566294037012424, -6.814217054740981]
same True
```

Important implementation detail:

```text
B is built from observed sample CN on the routes, not truncal CN.
```

That is:

```text
route.sample1_total_cn / route.sample1_minor_cn
route.sample2_total_cn / route.sample2_minor_cn
```

## Main CLI

The CLI entry point is:

```text
src/spur_codex/main.py
```

It now supports:

```text
reads CSV input
route enumeration
route scoring
single-seed scoring
multi-seed uncertainty loop
feature TSV output
```

Single-seed handling was fixed:

```python
seeds = [args.seed]
```

The RNG now uses the loop seed:

```python
rng = np.random.default_rng(seed)
```

Feature rows are written as:

```python
pd.DataFrame([score_results.score_features()])
```

Output path:

```text
{output_dir}/{input_file_stem}.tsv
```

For example:

```text
results/example_reads.tsv
```
