# SPUR Codex Progress Report

Date: 2026-06-09

## Batch Scoring Input Handling

Updated `src/spur_codex/main.py` so single-input and batch-input modes use the
same internal input-record structure:

```text
input_path
alt1
dep1
alt2
dep2
```

This fixed the batch-mode issue where `inputs` was constructed but the scoring
loop could still use the last `alt1/dep1/alt2/dep2` variables loaded. The
scoring loop now iterates over each input record and writes one feature TSV per
input file.

Feature output now includes `input_path`, which makes batch outputs traceable
to their original read-count file.

Also fixed the `--batch-filepath-list` parser declaration in
`src/spur_codex/arg_parser.py`.

## Runtime Reporting

Added terminal runtime reporting for each scoring round:

```text
Scored <input_path> seed=<seed> runtime_seconds=<seconds>
```

The feature TSV already stores `runtime_seconds`; the print is for live batch
monitoring.

The current RNG placement is:

```python
for input_record in inputs:
    for seed in seeds:
        rng = np.random.default_rng(seed)
```

This intentionally recreates the same RNG stream for the same seed for every
input profile, so Monte Carlo sampling is controlled across segments.

## Notes

Route count and MC sensitivity results should be interpreted per input segment
when ground truth may differ across segments. Pooling across the 10 input files
can hide segment-specific behavior.

For future MC variance experiments, more than 5 seeds would give a more stable
estimate of seed-to-seed variance. With only 5 seeds, the observed variance can
be non-monotonic as MC sample size increases.
